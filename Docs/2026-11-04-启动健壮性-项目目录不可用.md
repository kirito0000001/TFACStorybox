# 项目目录不可用时不要崩在启动（2026-11-04）

> 现象：双击程序，窗口还没出来就退出了。
> 日志（`%APPDATA%\GalExcleTools\crash.log` 与 `runtime.log` 都有）：
>
> ```
> System.IO.DirectoryNotFoundException: Could not find a part of the path 'G:\NewData\GalExcelProject'.
>    at AppSettingsService.EnsureProjectRootDirectory(...)   ← Directory.CreateDirectory
>    at MainWindow..ctor()
> ```

## 1. 根因

不是程序的逻辑错误，是**项目根目录所在的 G 盘没挂载**（移动硬盘没插 / 盘符变了）。
`Directory.CreateDirectory("G:\NewData\GalExcelProject")` 在盘不存在时抛 `DirectoryNotFoundException`，
而这条调用挂在 `MainWindow` 构造函数里，异常一路冒到 `App_UnhandledException` —— 进程直接结束。

**真正的问题是设计上的**：目录不可用是**可预期的环境问题**，不该等价于"程序不能启动"。
原来那条路径没有任何降级，用户连"去设置里改路径"的机会都没有。

## 2. 改法

### 2.1 `EnsureProjectRootDirectory` 不再抛

```csharp
private bool EnsureProjectRootDirectory(string projectRootPath)
{
    try { Settings.EnsureCurrentProjectRoot(); LoadAllCards(); return true; }
    catch (Exception error) when (error is IOException or UnauthorizedAccessException
        or NotSupportedException or ArgumentException)
    {
        AppendLog(LogKind.Error, "整体项目目录不可用：…（磁盘没插？盘符变了？）", error);
        ShowFloatingTip(Error, "整体项目目录不可用", "…已跳过项目载入，请到「整体设置」里重新指定。");
        Settings.SetProjectRootStatus(Error, "目录不可用", "…");
        return false;
    }
}
```

- 返回 `bool`，调用方据此决定下一步；**永不抛**。
- 同时把设置页那条状态置红 —— 用户被送过去之后得一眼看到问题在哪。

### 2.2 启动流程：失败就停在设置页

```csharp
var projectRootAvailable = EnsureProjectRootDirectory(Settings.ProjectRootPath);
ShowWorkbenchPage();
if (!projectRootAvailable) ShowSettingsPage();
```

停在空工作台上只会让人以为"项目全没了"，还得自己找设置入口。

### 2.3 导入入口也加守卫

`MainWindow.Workbench.Import.cs` 两处（项目包 / 素材库包）：
根目录不可用就直接 `return`，不再往下跑到导入阶段 —— 否则失败原因会绕好几层才显形。

## 3. 边界

- **不改用户设置**：`ProjectRootPath` 原样保留，插上盘重启就恢复；不会因为一次失败被重置成默认值。
- 只捕获 IO / 权限 / 非法路径这几类；其它异常（真 bug）仍然照常冒出去，不被这里吞掉。
- 顺带验证了昨晚那个「报错自动开日志」：这次崩溃的 `[Fatal]` 两行就是它写进 `runtime.log` 的。

## 4. 待验证

1. 编译。
2. 把根目录改到一个不存在的盘符（如 `Z:\Temp`），启动 → 应看到：窗口正常出现、浮条报错、
   自动停在设置页、状态红条写着"目录不可用"，程序**不退出**。
3. 改回正确路径 → 恢复正常。
4. 插着盘正常启动时，行为与以前一致（日志里仍有"已确认整体项目目录"）。
