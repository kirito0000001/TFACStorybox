## 0. 结论摘要

1. **剧情这边的管线其实不差**：它已经是「C# 只写清单和脚本，起**一次** `UnrealEditor-Cmd`，素材全由 Python 侧 `AssetImportTask` 导入」。所以慢的**不是**「每个文件起一次进程」，而是清单构建阶段的重复全量扫描、以及 Python 侧逐项 fsync 写进度。
2. **最该从零境学的是「在线 / 离线双路」**：编辑器开着时走远程执行（快约十倍、能读到离线读不到的资产），连不上才退回离线。剧情现在**只有离线一路**，而且检测到编辑器开着还会去**强关它**。
3. **第二该学的是「怎么判成败」**：零境一律看**结果文件是不是本轮写出来的**，不看退出码——因为 commandlet 只要工程里别处有编译错误就会返回非 0，拿退出码判会误报。
4. **零境的同步台 UI 是个反面教材**：整页约 1000 行直接写在 `MainWindow.xaml` 里，`Controls/` 目录一个都没用上。这点**不要照搬**——正好撞上本项目「能抽就抽，不在 Main 里硬叠」的规矩。
5. 剧情这边不需要六步向导：只要**选项目 + 选素材库 + 同步前检测文件夹**，然后同步。

## 1. 零境的做法（参考实现）

### 1.1 形态：分步向导，而且双向

- 步数唯一定义在 `Models/UnrealSyncWorkflow.cs:11-43`：`MaxStep = 6`，但 `IncludesEffectSyncStep = false` → 可见 5 步。
  **第 6 步是隐藏不是删除**（注释明写：代码、缓存、面板、脚本全留着，改回 `true` 就整条回来）。
- 六步：1 底层检测 / 2 同步素材 / 3 基础配置 / 4 序列同步 / 5 蓝图置入 /（6 特效同步·隐藏）。
- **方向**：`IsEngineToToolbox` 开关切「同步到虚幻 / 从虚幻导入」（`MainWindow.xaml:2102-2118`）。导入方向没有分步流程，只有一棵差异树。
- 导航语义（`ViewModels/UnrealSyncWorkflowController.cs`）：**进哪一步都不会自动跑 Unreal**，只落步号 + 读该步缓存；检测只能手动触发（「重新加载」/「依次检测后续步骤」）。这是用户当面提的要求。

### 1.2 核心：在线 / 离线双路 ← 最该学的一件

全部收在一个方法里：`Services/UnrealPythonTaskExecutionService.cs:41`

```csharp
UnrealPythonTaskLaunch BuildLaunch(editorPath, projectPath, scriptPath,
                                   remoteJobPath, offlineStartInfo,
                                   bool? useRunningEditor = null)
// → record UnrealPythonTaskLaunch(ProcessStartInfo StartInfo, bool UsesRunningEditor)
```

调用方只认这个 record，不关心走哪条路。

**怎么判定编辑器在跑**（`ShouldUseRunningEditor`，同文件 `:114`）：

- `Process.GetProcessesByName("UnrealEditor")`
- **刻意不用 WMI**（避免引入 `System.Management`），改用「主模块路径 + 主窗口标题」拼一个描述串：`$"{modulePath}|{MainWindowTitle}"`（`:194`）
- 项目匹配：描述串含 `.uproject` 绝对路径，**或**标题按空格/`-`分词后含项目名（标题形如 `Lvl_Xxx - CrossingVoid`）
- 引擎匹配：能拿到引擎根时要求描述串含它
- `:108-113` 记录了旧 bug：只判进程名时，开着别的工程（DevTest）也会走在线路，然后在连接阶段整个失败

**两条路怎么执行**：

| | 在线（编辑器开着） | 离线（编辑器没开） |
|---|---|---|
| 启动 | 引擎自带的 `Engine/Binaries/ThirdParty/Python3/Win64/python.exe` 跑 `Tools/UnrealBridge/run_remote_unreal_job.py --job <job.json>` | `UnrealEditor-Cmd.exe <uproject> -run=pythonscript -script=<py> -unattended -nop4 -nosplash` |
| 实际执行 | Unreal **Python 远程执行协议**（`remote_execution.RemoteExecution()` → 按 `project_root`+`engine_root` 找节点 → `run_command`），脚本在**已在运行的编辑器里**跑 | 冷启一个无头编辑器 |
| 传参 | 写 job.json，**只转发 `ZD_` 前缀环境变量** | 子进程环境变量 |
| 耗时 | 「快约十倍」 | 冷启动十几秒到 40 秒 |

**回退规则**（`MainWindow.UnrealSync.Shared.cs:52-81`）：

- 只有「连不上编辑器」才回退——脚本自己失败**不**回退（"退回去也是一样的错，白等一次编辑器冷启动"）
- 判据是输出里带标记 `ZD_REMOTE_UNAVAILABLE`（`UnrealPythonTaskExecutionService.cs:25`）
- 回退时写 warning 日志 + 弹一条「已退回离线执行」提示条
- 没匹配到在线时也**记一行痕**，免得用户困惑于「怎么突然慢了 40 秒」

**能力差异（只有在线能做）**：

1. 在编辑器里**定位资产**——离线直接拒绝（`Services/UnrealAssetBrowseService.cs:28-29`）
2. 读「类由编辑器模块提供」的资产：离线读不到 `WidgetBlueprint` / `MetaSoundSource`。
   实测同一工程**在线 23 项 0 错、离线 4 项全报未找到** → 于是专门加了 `UnrealLightConfigurationStatus.Unavailable`：**不算错误、不进错误计数、不往第一步挂错误**
3. 速度

### 1.3 判成败：结果文件新鲜度，不看退出码 ← 第二该学

`Services/Infrastructure/UnrealProcessRunner.cs`：

- 起进程 / 500ms 轮询进度文件 / 超时 / 取消时**先杀进程树再抛**
  （`:24-29` 记着原设计的坑：`await Task.Delay(ct)` 直接掀掉循环，顶部那句 `Kill` 永远轮不到，`using var process` 又不结束进程 → `UnrealEditor-Cmd.exe` 成孤儿占着工程锁）
- **成败判定做成 `verdict` 回调**（`:52-56`），因为「commandlet 退出码不可靠、各链路规则不同」
- `IsFreshOutput`（`:158-159`）：结果文件**本轮**写出来了才算成功
- `StandardOutputEncoding = UTF8` + `PYTHONUTF8=1`：不这么写，中文 Windows 按 936 解码，远程执行的报错必然乱码——而这条路的错只能从这段输出看

### 1.4 长流程的进度与取消

- `Services/WorkflowProgressPlan.cs`：**「阶段 N/M」按实测耗时加权分配**（同步前导出 15s / 备份 66s / 桥接 13s / 复扫 15s），不是写死数字；`Band.At()` 把子进度映射进区间；末尾留 2% 尾巴
- 没有百分比的长任务退化：备份报「已写入 N MB · 用时 mm:ss」，按 66 秒参照推进、封顶 95%（`MainWindow.UnrealSync.Shared.cs:214-222`）
- 取消：点环形进度条 → 确认框（明说「已写入的文件可能保留」）→ `Cancel()`

### 1.5 缓存与状态：一步一个文件 + 纯函数投影

- 每步**自己的**缓存文件，落 `<角色>/<工具目录>/UnrealSync/`：`step1-foundation.json`、`step2-material-sync.json`、`step3-light-configuration.json`、`step4-sequence-sync.json`、`step5-blueprint-setup.json`、`session.json` …
  这是**刻意的返工**，取代旧的「所有步骤共用一大坨」——那份串台过好几次（`Step1FoundationCache.cs:15-18`）
- `ViewModels/UnrealSyncWorkflowState.cs`：「现在这一步该显示什么」抽成**纯函数**，只吃布尔和计数，**可以脱离 WinUI 直接断言**。注释明写以前是「六十行嵌套三元，和集合、字段、界面类型缠在一起，只能靠跑起界面去看」
- `UnrealSyncStepLoadStore.cs`：把「差异树归第二步还是第四步」写成不变式，越界直接抛

### 1.6 零境的欠债：别照搬的地方

- 同步台整页 `MainWindow.xaml:2088-3088` ≈ **1000 行**直接写在 `MainWindow.xaml` 里，**`Controls/` 目录一个都没用**（`controls:` 引用全在别的页）
- 这是明确的可维护性欠债。**移植时必须拆控件**，否则等于把对方的债搬过来。

## 2. 剧情的现状

### 2.1 管线：其实已经是「一次进程」

`Services/UnrealSyncService.cs:969-1042`（`Run`）：

1. C# 写 `Saved/GalExcleTools/gal-sync-manifest.json`
2. C# 写 `gal_sync_import.py`（**`WritePythonScript`，S:307-990，约 683 行的内嵌字符串**）
3. 起**一次** `UnrealEditor-Cmd.exe -ExecutePythonScript=<py> -unattended -nop4 -nosplash`（S:1002、S:1008）
4. 每秒轮询进度文件，30 分钟超时，取消即 Kill

**素材不复制**，全部由 Python 侧用 `AssetImportTask` 导入。这个思路和零境是一致的、没错。

**只有离线一条路**：全项目唯一的 `-ExecutePythonScript` 就在 `S:1002`；`ResolveEditorExecutable`（S:1606-1639）只接受 `UnrealEditor-Cmd.exe`，找不到才回落 `UnrealEditor.exe`。

而且 `MainWindow.UnrealSync.Process.cs:79-139` 会**用 WMI 查同名 `.uproject` 的 UE 进程 → 弹窗 → 可强关**，且这个 WMI 查询是在 **UI 线程同步执行**的（`MainWindow.UnrealSync.cs:342` → `Dialogs.cs:64`）。

> 这一步的语义和零境**正好相反**：零境是"编辑器开着就利用它"，剧情是"编辑器开着就问你关不关"。

## 3. 建议方向

### 3.1 形态：不做六步向导

零境的向导是为「角色动作帧 + 序列 + 蓝图」那种多阶段、可分批的流程设计的。剧情这边你说了只要「选项目 + 选素材库」，那么：

- **保留单页**，重做布局
- 顶部：项目选择 + 素材库选择（**新增**：现在同步台选不了素材库，是从项目推导的）
- 中部：**同步前检测面板**（学零境第一步的形态：一张「检查项 / 期望 / 实际 / 是否合规」的表）
- 底部：变更清单（现在那串 TextBlock）+ 同步按钮

### 3.2 必做的四件事

1. **判成败改成「结果文件新鲜度」**，不看退出码 —— 这条单独就能消掉一批假失败
2. **服务拆开**：`UnrealSyncService.cs` 按职责拆成
   `UnrealSyncPathPolicy`（路径/命名）、`UnrealSyncManifestBuilder`（清单与变更计划）、`UnrealSyncScriptWriter`（Python 脚本，**外置成 .py 资源文件**）、`UnrealSyncRunner`（起进程/轮询/超时/取消杀树）
3. **UI 抽控件**：`Views/UnrealSyncPanel.xaml`，而不是继续堆在 `MainWindow.xaml`（现在这页 947 行）
4. **补 VM**：把按钮可用性、状态文案、进度收到 `UnrealSyncViewModel` 里，别再用「借按钮点击传参」这种手法

### 3.3 在线路要不要做（这是最大的技术投入）

| 选项 | 代价 | 收益 |
|---|---|---|
| **A. 不做**，只把离线做快做稳 | 小 | 消掉重复扫描后，离线冷启动那 40 秒仍在 |
| **B. 做双路**（学零境 `BuildLaunch` + `ZD_REMOTE_UNAVAILABLE` 回退） | 中：需要 ① 一个走远程执行协议的 .py ② 编辑器匹配判定 ③ 回退与痕迹日志 | 编辑器开着时快约十倍；能读离线读不到的资产；**不再需要"强关编辑器"** |
| **C. 先做 B 的骨架**，只给「同步」这条链路走在线，其余仍离线 | 小-中 | 大部分收益，风险可控 |

我倾向 **C → B**。另外无论选哪个，**「检测到编辑器开着就强关」这一步建议直接删掉**——它的 WMI 查询还在 UI 线程上同步跑。

### 3.4 「检测文件夹是否存在」怎么定

零境第一步的口径值得直接抄：

- **纯磁盘扫描，不跑 Unreal**（所以便宜，可以进页面就跑）
- 检查项做成一张表：`显示名 / 期望路径 / 实际路径 / 是否合规 / 问题 / 期望类型 / 实际类型`
- **legacy 命名存在但不符合规范，仍判不合规**，`Problem = "命名不规范"`（而不是当成通过）
- **只读，不自动创建**，明确要求用户去 Unreal 内容浏览器整理
- 严格档才抛异常拦住流程；宽松档只显示

剧情这边要检测哪些目录，**需要你给对接口**。
