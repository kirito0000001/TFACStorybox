# 语音页三个新按钮 + 统一弹窗组件（2026-11-04）

## 1. 工具栏新增

| 按钮 | 形态 | 作用 |
|---|---|---|
| 语音设置 | 图标（`SymbolIcon Setting`） | 弹窗：**音轨数**（1–8）、**同步播放**开关、**说话人标识**勾选 |
| 筛选 | 图标（`E71C`）+ 菜单（代码生成） | 全部行 / 已设置语音 / 未设置语音 / 未检查 / 缺少设置 / 〔动态〕xxx语音 |
| 音轨 N | 文本按钮 | 多音轨时点开切换；只有一条时置灰并说明原因 |

原来那个「仅看已设置 / 显示全部」的开关被筛选菜单取代（同一位置，功能是它的超集）。

### 1.1 筛选的分组（2026-11-04 二次调整）

- 文案去掉了"只看"两个字 —— 筛选本来就是"只看"。
- **缺少设置**：说话人那边勾了"该角色有语音"，但这行还没配文件。
  这是唯一能"按预期找出漏配"的项 —— 光看「未设置」会把旁白一起带出来。
- **xxx语音**：按当前章节的说话人**动态生成**，显示中文名（`夏疏影语音`）。
  菜单在代码里重建（`RebuildVoiceFilterFlyout`），章节一换就跟着换。
- 原有的「超差」项被移除：规整按钮本身只在有超差项时才亮，不需要再筛一遍。

### 1.2 说话人键的归一化

同一章里同一种写法可能有多种字符：`？`(U+FF1F) 与 `?`(U+003F) 长得一样但不是同一个串。
`ToSpeakerKey` 做 NFKC 归一（全角→半角）+ 折叠空白，**只合并"同义写法"**。
`?` 与 `???` 是两个不同角色，不合并（用户明确要求）。

## 2. 音轨：先接一半，另一半说明白

- 已做：音轨数、当前音轨、切换、持久化到 `{项目}/Tools/voice.settings.json`。
- **没做**：每行在每个音轨上的**文件落位**。

原因：`story.voice-map.json` 是「行 Id → 一个文件路径」，多音轨要改成
`行 Id + 音轨号 → 路径`。那是改映射结构，写坏了就是真丢语音。
所以这一步只把选择记住，并在切换时明说"文件映射还没接"，不假装已经支持。

设置单独存一个文件，而不是塞进映射表 —— 偏好坏了顶多回默认值，别让它有机会碰映射。

## 3. 统一弹窗组件 `Controls/ToolboxDialog.cs`

与 `TipToast` 同一套思路：**单文件、无 XAML、零 ThemeResource**，拷到别的项目改 namespace 就能用。

```csharp
await ToolboxDialog.ConfirmAsync(RootGrid.XamlRoot, "标题", "内容");
await ToolboxDialog.ShowAsync(RootGrid.XamlRoot, "标题", "内容");
await ToolboxDialog.ShowAsync(RootGrid.XamlRoot, "标题", UIElement, "保存", "取消");
ToolboxDialog.BuildForm(...) / BuildField(...)   // 统一间距的表单
```

内部要点：

- 内容统一套 `ScrollViewer`（`MaxHeight=460`）——长报错不会把弹窗撑成细条；
- **抢不到弹窗时返回 `None`**：WinUI 同一个 XamlRoot 只允许一个 ContentDialog，
  抢不到会抛异常。组件自己兜住，不让调用方断在业务流程中间。
- 没有主按钮时 `DefaultButton = Close`，避免回车误触。

> 现状：只给语音设置用。后续把 `IDialogService` 那几个调用点逐步换过来，
> 统一之后再删旧的，不一次性大改。
