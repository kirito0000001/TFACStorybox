# 立绘结构参考（基于《ライムライト・レモネード・ジャム》解包）

> 数据来源：`fgimage.xp3`（541 MB）解包，1185 张 TLG5 图像
> 解包方法与 key 见 `拆分学习/解包记录.md`
> 记录时间：2026-11-07

## 一、数量与结构

| 项目 | 数量 |
|---|---|
| `fgimage.xp3` 解出文件 | 1232 个 |
| TLG5 图像 | **1185 张** |
| PSB（合成定义/脚本） | 47 个 |
| 大图（高 ≥ 2000 px，全身/半身） | **217 张**，187 种不同尺寸 |
| 小件（高 < 300 px，表情零件） | 917 张 |
| 中件（300 ≤ 高 < 800） | 50 张 |

**结论：差分不是"整张立绘 × N 套"，而是「一张基础身体 + 一堆表情零件」。**

证据是尺寸分布：大图都是 600~1700 宽、3300~4250 高（整身），
小件集中在 120~420 宽、55~380 高（眼、口、眉、腮红这类）。

## 二、分辨率实测

| 类别 | 尺寸范围 | 典型值 |
|---|---|---|
| 全身立绘 | 642×3380 ~ 1712×4253 | **约 1500×4200** |
| 表情零件（眼/口/眉） | 123×112 ~ 420×378 | **约 334×249** |
| 腮红/汗/泪这类小件 | 高 55~300 | — |

> 他们的游戏是 1080p，立绘按 **约 2 倍** 的余量画（4200 高 ≈ 两倍屏高），
> 不是"越大越好"，而是"够放大就行"。

---

## 三、差距：自家立绘 6000×8000

```
参考作品  1500 × 4200   ≈ 6.3 MP
自家      6000 × 8000   = 48 MP   ← 7.6 倍面积
```

**这不是"更精细"，是浪费：**

1. 引擎里最终显示尺寸只有 1080p 级别，多出来的像素被双线性缩掉；
2. 显存/包体按 48 MP 算，6 张角色就是 300 MP，压缩后依然巨大；
3. 画师在 6000×8000 上画，笔刷细节反而会因为缩放丢失；
4. 差分（表情）在这么大画布上要重画，成本翻倍。

**建议目标**

| 用途 | 建议尺寸 |
|---|---|
| 1080p 项目的全身立绘 | **1400 × 4000**（约 2 倍余量） |
| 表情零件（眼/口/眉） | **400 × 300** 左右 |
| 腮红/汗/泪 | 200 × 200 以内 |
| 如果要 4K 支持 | 全身 **2000 × 5600**，不必更高 |

## 四、命名：已还原（1140 / 1232）

用现成的名称表一次性解决：

```
https://github.com/MLChinoo/lllj_hxnames  →  HxNames-LLLJ.lst（61335 条，5.2 MB）
格式：<64位大写哈希>:<原始文件名>
```

映射后 **1140 / 1232 命中**（92 条缺失是版本差异/补丁新增），原始文件名全部恢复。

### 命名规则

```
<角色><姿势>_<部件编号>.tlg      例：恵凪a_3782.tlg
<角色><姿势>.pbd                 例：恵凪a.pbd      ← 图层/合成定义
<角色><姿势>.sinfo               例：美玖a.sinfo    ← 部件位置尺寸
<角色><姿势>.stand               例：傑.stand       ← 站立定义
emotion.csv / facethumbpos.csv / facezoom.csv      ← 表情/缩略图配置
```

**注意：文件名里只有"编号"，没有语义名**（没有 eye/mouth/base 这类）。
部件语义（眼/口/眉/腮红）存在 `.pbd` / `.sinfo` 里，两者都是 **PSB 格式**，
需要 FreeMote 的 `PsbDecompile` 才能读成 JSON。

## 五、给画师的差分表模板

按"基础身体 + 零件"组织，而不是"每个表情一张整图"：

| 角色 | 基础身体 | 眼 | 口 | 眉 | 附加 |
|---|---|---|---|---|---|
| 角色 A | 身体 1（站立）<br>身体 2（侧身） | 开/半/闭/笑眼/生气眼 | A/I/U/E/O/微笑/张嘴 | 普通/皱眉/八字 | 腮红 2 档、汗、泪、阴影 |
| 角色 B | … | … | … | … | … |

这样画师的产出是「**3~5 张身体 + 30~50 个零件**」，
而不是「每个表情一张 1500×4200」——后者 20 个表情就是 20 倍成本。
