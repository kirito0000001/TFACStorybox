# 工具箱开发规范

这份规范用于所有 GalExcleTools 风格的 WinUI 工具箱。以后制作新的工具程序，或者继续扩展零境 ZD 角色制作工具箱，都按这份标准执行。目标是让架构、界面手感、进度反馈、构建验证流程都稳定复用。

## 1. 架构基线

所有工具箱都按同一套职责拆分：

- `ApplicationViewModel`：根 ViewModel，只聚合模块和跨页面状态，不写具体业务。当前固定挂载 `SettingsViewModel`、`GlobalProgressViewModel`、`ProjectWorkbenchViewModel`、`AssetLibraryViewModel`、`StoryEditorViewModel`、`UnrealSyncViewModel`。
- `Models`：序列化数据、不可变摘要、操作结果、进度记录、领域数据。不能引用 WinUI 控件。
- `Services`：文件系统、JSON/CSV 解析、哈希校验、目录迁移、导入导出、备份还原、Unreal 同步、图片/音频处理等领域操作。可以接收 `IProgress<T>` 和 `CancellationToken`，但不能直接更新控件。
- `ViewModels`：页面状态、校验状态、命令、选中项、给用户看的状态文字，以及对 Service 的编排。ViewModel 继承 `ObservableObject`，公开可绑定属性。
- `Views`：可复用控件、对话框内容工厂、纯 UI 组合。可以创建 WinUI 元素，但不要放业务规则。
- `Styles` / 资源字典：按钮风格、面板、字体层级、间距、图标按钮行为等公共视觉规则。
- `MainWindow`：只做应用壳和桥接。允许负责启动连接、自定义标题栏、导航选择、文件/文件夹选择器、`XamlRoot`、页面进入动画、全局进度条宿主，以及调用 ViewModel 或对话框服务。

`MainWindow.xaml.cs` 不能变成“所有功能实现文件”。只要涉及解析、扫描、校验、迁移、同步规则、导出规则、命名规则或持久化状态，就先建立或扩展 ViewModel 和 Service，再从窗口调用。

模块必须分类登记：项目工作台属于 `Project`，素材库属于 `Asset`，剧情编辑器属于 `Story`，Unreal 同步属于 `Integration`，整体设置属于 `Settings`，标题栏、导航、进度条和对话框桥接属于 `Shell`。

## 2. MainWindow 允许做什么

允许放在 `MainWindow` 里的内容：

- 创建应用壳，设置标题栏、图标、窗口初始位置。
- 承载 `NavigationView`，通过一个集中方法切换页面显示。
- 页面显示时播放统一进入动画。
- 打开需要窗口句柄的 WinUI 选择器。
- 通过对话框服务提供 `XamlRoot`。
- 显示、更新、取消、完成、隐藏底部全局进度条。
- 把 UI 事件桥接到 ViewModel 命令或异步方法。

不要放在 `MainWindow` 里的内容：

- 文件复制、哈希、JSON/CSV 解析、压缩包生成、Unreal 同步规则、素材索引、备份逻辑。
- 大段校验逻辑。
- 本该绑定的页面状态，却在代码里手动改控件。
- 服务里已有的重复工具方法。
- 绕过公共样式的一次性对话框或进度条。

如果一个新的事件处理函数超过了“桥接”的范围，就先抽出去再继续写。拆成 `MainWindow.*.cs` 只是第一步，不能把业务规则永远留在窗口分部；能脱离控件运行的路径、命名、索引、校验、导入、导出和同步规则必须继续下沉到 Service。

## 3. ViewModel 规则

- 一个主页面对应一个主 ViewModel。复杂面板可以拆子 ViewModel。
- 不要把 `MainWindow` 迁移成另一个巨大的 ViewModel。超过一个页面职责的状态必须拆成子 ViewModel。
- 根 ViewModel 只负责聚合、导航状态和跨页面服务入口，不直接做文件扫描、卡片加载或业务校验。
- ViewModel 负责可绑定状态，比如路径文本、选中项、状态标题、状态消息、状态严重级别、忙碌状态、命令可用状态和校验结果。
- 可复用动作使用 `RelayCommand` 或 `AsyncRelayCommand`。只有 WinUI 基础设施强依赖时，才保留原始点击事件，比如 `FolderPicker` 或 `ContentDialog`。
- 异步命令默认要防止重复执行，除非功能明确支持并行。
- ViewModel 可以编排 Service，但耗时和领域逻辑仍然放 Service。
- ViewModel 通过构造函数接收 Service，不要在事件处理里临时到处 new 领域服务。
- 如果文字反映的是功能状态，放 ViewModel；如果只是进度条动画里的瞬时文本，放全局进度条宿主。
- 允许 `MainWindow` 分部暂时桥接旧控件，但持久状态必须优先落在对应模块 ViewModel：项目工作台、素材库、剧情编辑器、Unreal 同步、整体设置各自独立，不要把状态塞回窗口字段。

## 4. Service 规则

- Service 必须是可测试、脱离窗口也能运行的确定性单元。
- 任何可能耗时的操作都要接收 `CancellationToken`。
- 任何可能扫描、复制、导入、导出、同步、哈希、压缩、删除多个文件的操作都要接收 `IProgress<T>`。
- 进度记录至少包含 `Message`、`Percent`，可选 `Detail`。总量未知时使用 `IsIndeterminate`。
- Service 返回结果记录，包含数量、路径、警告、变更摘要等，不要直接修改 UI 状态。
- 破坏性操作必须先验证新状态，再删除旧状态。目录迁移按“复制、大小/哈希校验、保存设置、删除旧目录”的顺序执行。

## 5. 全局进度条标准

所有耗时或潜在耗时操作都使用底部全局进度条，不再创建单独的进度对话框。

全局进度状态归 `GlobalProgressViewModel`。窗口层只保留动画、可见性过渡、取消点击和圆环几何绘制。

必要行为：

- 开始时调用 `ShowGlobalProgress(title, targetName)`。
- 立刻报告初始步骤，即使当前文件很少。
- 操作中更新消息、百分比、详情、耗时和环形进度。
- 可以安全停止的操作，通过圆形进度控件提供取消。
- 完成时显示清晰的成功、失败或取消信息。
- 延迟一小段时间后隐藏，让用户看见结果。

必须使用全局进度条的场景：

- 整体项目目录迁移。
- 文件夹备份、导出、导入、还原。
- 素材索引同步和修复。
- Unreal 同步。
- 图片或音频批量处理。
- 任何多文件扫描或哈希校验。

## 6. 提示、弹窗和快捷键

- Tips 和帮助说明使用对话框服务创建 `ContentDialog`。
- 内容可能超过可见高度时，对话框内部使用 `ScrollViewer`。
- 对话框要保留常用快捷键：`Enter` 确认默认动作，`Esc` 关闭或取消；非破坏性的提示弹窗如果项目已有右键关闭习惯，也继续支持右键关闭。
- 页面里的小帮助按钮使用公共圆形问号按钮样式，并带 tooltip。
- 不要把详细说明做成常驻的大 `InfoBar`。`InfoBar` 用于当前状态、成功、警告、错误。
- 小页面都要考虑键盘手感。重要快捷键可以写在实现附近或 ViewModel 注释中，不要在界面上铺满教学文字。

## 7. 导航和页面动画

- 主页面切换通过一个集中方法完成：隐藏所有非目标页，只显示目标页。
- 每个主页面进入时播放同一套动画：从左侧滑入并淡入。
- 当前基准：偏移 `-96`，时长约 `280ms`，透明度 `0.82 -> 1`，`CubicEase` 的 `EaseOut`。
- 不要随意新增另一套页面动画。确实需要时，先把规则补进这里。

## 8. UI 手感和按钮规则

- 应用壳使用较高的自定义标题栏、左侧紧凑导航、Mica 背景、克制的面板和稳定间距。
- 使用公共样式，比如 `PanelBorderStyle`、`IconToolButtonStyle`、`HelpIconButtonStyle`。
- 紧凑命令优先用图标按钮，并提供 tooltip。
- 文本按钮用于明确的文字动作，比如选择文件夹、关闭弹窗。
- 不要把页面分区做成层层嵌套的装饰卡片。面板用于真实分组，重复卡片只用于代表单个条目。
- 文本在桌面和较窄窗口里都必须装得下。紧凑面板里不要使用过大的标题。
- 工具箱界面要安静、实用、可反复操作，不做营销页手感。

## 8.1 性能规则

- 大列表不要一次性创建大量控件，按批次加入并在批次之间让出 UI 线程。
- 图片预览按路径缓存，切换素材库或角色时取消旧加载。
- ViewModel 不做图片解码、哈希、压缩、CSV 扫描等重活；这些都放 Service。
- 绑定属性保持轻量，不在 getter 里做文件系统扫描或复杂计算。
- 拖拽排序、批量导入、规范化命名、同步检查都要支持取消和进度。
- 页面切换时不要重复重建稳定数据，优先复用缓存并在必要时刷新。

## 9. 整体项目目录规则

每个有共享项目目录的工具箱都按这个模式做：

- 设置保存在 `AppSettingsService`。
- 默认路径固定在 `D:\`，例如 `D:\CrossingVoidZDProject`。
- 用户选择的是父目录，程序自动追加固定项目文件夹名。
- 新路径和当前路径相同，只显示提示，不执行迁移。
- 新路径位于旧目录内部时，必须阻止迁移。
- 迁移时先复制目录和文件，逐个文件做大小/哈希校验，更新设置，确保新目录存在，再删除旧目录。
- 每个阶段都要报告进度，哪怕现在项目里文件很少。

## 10. 编码和编辑规则

- `.cs`、`.xaml`、`.json`、`.md` 文件保持 UTF-8。
- 不用 PowerShell 重定向直接改源码，避免中文和 XAML 转义被破坏。
- 补丁要小。改 XAML 或中文字符串前先读附近代码。
- 修改中文后用 UTF-8 重新打开检查，不能出现乱码。
- 工作区里用户已有的无关修改不要回滚。

## 11. 构建、启动和邮件通知流程

只要修改了 C#、XAML、项目文件、资源或打包逻辑，就按这个流程收尾：

1. 先构建一次。
   - 剧情工具箱：`powershell -NoProfile -ExecutionPolicy Bypass -File .\Scripts\Test-SourceHealth.ps1 -Build`
   - 普通 WinUI 工具箱：`dotnet build <Project>.csproj --configuration Release --runtime win-x64 -p:Platform=x64`
2. 构建成功后，直接从输出目录短启动一次程序。这样能及时发现运行期 XAML、资源、图标、标题栏、启动连接问题。
   - 如果用户要求“启动后不用关闭”，启动检查后保留程序运行，不要为了清理验证进程而关闭它。
3. 如果任务包含打包，源码健康检查通过后再运行打包脚本，并检查打包输出。
4. 一个有意义的步骤完成或最终验证完成后，使用 `C:\Users\liuyu\Documents\CodexTools\notify-step.ps1` 发送邮件提示。如果邮箱凭据不可用，就说明未能发送，但不要因此阻塞代码工作。

没有尝试构建和短启动，或者没有明确说明阻塞原因，就不能说任务完成。

## 12. Git 流程

- 修改范围完整时可以做本地提交。
- 用户没有明确要求时不要推送 GitHub。这个工具箱系列通常等一个版本节点完成后再推送。
- 不要回滚用户已有的无关修改。
- 提交前检查 `git status --short`，只暂存本次需要的文件。

## 13. 新工具箱复用清单

新建另一个工具箱时，先复制这套骨架，再加功能：

- 带默认项目目录的 App 设置服务。
- 对话框服务和对话框内容工厂。
- Observable ViewModel 基类和命令辅助类。
- 公共按钮、面板、字体样式。
- 带应用图标和版本号的自定义标题栏。
- 紧凑导航和页面进入动画。
- 可取消的底部全局进度条。
- 从剧情工具箱模式复制整体设置页，再按新项目删减。
- 项目专属偏差写进内部文档。
- 构建、短启动、邮件通知流程。
- `Docs/ToolboxArchitectureMigration.md` 或等价文档，用来记录当前项目的模块分类和继续迁移路线。

## 14. 完成前检查标准

收尾前逐项检查：

- `MainWindow` 是否只剩壳层和桥接职责？
- 新功能逻辑是否放进 ViewModel/Service？
- 长操作是否可取消、可汇报进度？
- Tips 和对话框是否使用公共模式和快捷键？
- 页面动画是否一致？
- 是否已经构建？
- 构建后是否短启动过程序？
- 是否尝试发送邮件通知？
- Git 是否只做本地提交，除非用户明确要求推送？

## 15. MainWindow 退出标准

剧情工具箱当前处于“根状态和模块状态已迁移，窗口已按页面/功能拆成分部文件，业务规则继续下沉”的阶段。以后每次改功能都要顺手减少 `MainWindow` 分部里的业务面积。

`MainWindow` 最终只应保留：

- 构造函数组合服务和 ViewModel；
- 标题栏、图标、窗口初始位置；
- 导航切页和页面进入动画；
- 文件/文件夹选择器；
- `ContentDialog` 的 `XamlRoot` 桥接；
- 全局进度条动画、取消点击和圆环路径；
- 少量事件转发到 ViewModel 命令。

以下内容必须逐步移出：

- CSV 行逻辑、章节导入导出、索引修复；
- 素材库扫描、音频规范化、图片转换、角色层级规则；
- Unreal 同步校验、变更计划、外部进程规则；
- 项目和素材库的创建、重命名、删除、备份、还原编排；
- 可绑定状态的手动控件赋值。
