# 素材页问题清单（2026-10-17 用户反馈 + 自查）

用户原话：「拖动触发后没有生成图片预览在鼠标上，鼠标移动到对应位置时没有边框高亮提示，
背景图加载一次非常久，需要做预加载或者接入进度条，然后素材不需要延迟刷新（经常打断我预览），
还有改名或者改顺序后素材没有立即刷新，然后从别的分区回来时没有记录上次离开位置，
需要重新点进去位置，还有从素材细节面板退出时是直接回到了最开头，而不是素材打开的位置。
反正问题很多，你记录一下后自己再检查一遍吧」

按"现象 / 可能根因 / 建议做法"记录；末尾是我自查补的条目。

## 一、用户反馈的七条

### 1. 拖动时鼠标上没有图片预览（拖拽幽灵图）
- **现象**：拖动素材时，光标下没有那张图的小预览。
- **可能根因**：素材页的拖拽（旧网格）已退休，现在排序走「移动素材」（无拖拽）；若用户指的是
  **角色详情页的图层拖拽**或**从资源管理器拖入**，那两条用的是框架默认拖拽视觉 ——
  WinUI 的 `DragStarting` 若不给 `DragUI`，就只有默认的"半透明缩略"或什么都没有。
- **建议**：在 `DragStarting` 里设 `args.DragUI.SetContentFromSoftwareBitmap(...)`（用卡片缩略图），
  或在 `DataPackage.Properties` 里带 `Thumbnail`。涉及：详情页的图层拖拽处理器。

### 2. 鼠标移到目标位置没有边框高亮
- **现象**：拖动/移动过程中，目标卡片没有高亮提示。
- **现状**：我在「移动素材」里做了 3px 描边高亮（`Card_PointerMoved` + `ClearMoveTargetHighlight`），
  但**只挂了背景图与音频的卡片**（`FillAssetBrowserWithBackgroundsAsync` / `FillAssetBrowserWithAudio`
  / `FillAssetBrowserWithPropImagesAsync` / 滤镜填充）。若用户指的是**拖拽**（非移动模式），那确实没有。
- **建议**：先确认是哪条路径；若是拖拽，加 `DragOver` 时的 `BorderThickness` 变化（旧网格本来有这套）。

### 3. 背景图加载一次非常久 —— 要预加载或进度条
- **现象**：进背景图分类要等很久。
- **根因（已实测）**：大 PNG 首次解码 50~95 ms/张（`DecodePixelWidth=1280`），60 张就是 3~6 秒；
  且是**串行**在 `FillAssetBrowserWithBackgroundsAsync` 里逐张 await。
- **建议**：① 并行解码（`Task.WhenAll` 分批，注意 UI 线程）；② 降低解码尺寸（缩略图不必 1280）；
  ③ 磁盘缩略图缓存（按 文件路径+大小+修改时间 做 key）；④ 先铺占位卡再逐张回填；
  ⑤ 复用现有的 `GlobalProgressHost` 进度条（`MainWindow.Progress.cs`）显示进度。

### 4. 素材不需要"延迟刷新"（经常打断预览）
- **现象**：操作后过一会儿界面自己刷新，打断正在看的预览。
- **根因**：`RequestDelayedRefresh()`（多处调用，46 处以上）会在延迟后重铺界面。
- **建议**：加"预览中不刷新"的守卫 —— 查看器页（`BackgroundImageViewerPage`）或播放器页可见时
  只标记 `_pendingRefresh = true`，回到素材页再执行。

### 5. 改名 / 改顺序后素材没有立即刷新
- **现象**：改完备注或移动素材后，卡片上还是旧的。
- **根因**：`RefreshCurrentAssetCategoryAsync()` 依赖 `_currentAssetCategoryKey`，
  而它在**回到分类层时被清空**（`FillAssetBrowserWithCategories` 里 `= null`）——
  若用户在查看器/播放器里改的备注，回到素材页时 key 已是 null → 重铺变成 no-op。
- **建议**：把"重铺"改成不依赖 key：直接重铺当前可见的那一层（分类层就重铺分类卡，
  分类内就重铺该分类）；或在改备注/替换/删除后**记住"来源分类"**再重铺。

### 6. 从别的分区回来不记得上次位置
- **现象**：切到别的分类再回来，要重新滚到原来的位置。
- **建议**：按分类 key 记 `ScrollViewer` 的垂直偏移（浏览器网格在 ScrollViewer 里时用
  `ChangeView`），或记"上次选中的卡片"并在返回时 `ScrollIntoView`。

### 7. 从素材细节面板退出时回到最开头
- **现象**：从查看器/播放器返回素材页，滚动位置回到顶部。
- **根因**：返回时走 `RefreshCurrentAssetCategoryAsync()` 重铺卡片 → 网格被清空重建 → 滚动归零。
- **建议**：同第 6 条（记录偏移 + 恢复）；或改成"不重铺，只更新那一张卡片的内容"。

## 二、我自查补上的

### 8. 分类卡没有图标、计数不即时刷新
- 零境的库卡是"文件夹图标 + 名字"，我们目前只有"名字 + 数量"；
- 数量只在打开素材库时算一次（导入 / 删除后不更新）。

### 9. 「移动素材」没有 Esc 取消
- 现在只有"右键取消"与"点自己取消"；Esc 需要挂到素材页的键盘处理上。

### 10. 导入入口与新建角色入口缺失（已在另两份文档记录）
- 导入：`Docs/2026-10-17-素材页导入入口待补.md`（服务方法都在，4 个 `Add*Button_Click` 保留待复用）；
- 新建角色：`CreateCharacterAsync`（`CharacterDetail.cs:45`）逻辑还在，入口随旧立绘网格删除。

### 11. 详情页 / 查看器与素材页的返回路径不统一
- 查看器（`ShowBackgroundImageViewerPage`）与播放器返回时都重铺素材页；
- 建议统一成"返回即恢复现场"（位置 + 不重铺）。

### 12. `RefreshCurrentAssetCategoryAsync` 的语义偏窄
- 它只认"当前打开的分类"，对"分类层"与"刚返回"两种情形都是 no-op ——
  这是第 5、7 条的共同根因，建议一并改造（见第 5 条的建议）。

## 三、建议的处理顺序

1. **先修"刷新时机"这一类**（第 4、5、7、12 条是同一个根因：重铺太粗暴）——
   收益最大，且能顺带解决"打断预览"；
2. 再做**滚动位置记忆**（第 6、7 条）；
3. 然后**性能**（第 3 条：并行 + 降解码尺寸 + 缓存 + 进度条）；
4. 最后是**观感细节**（第 1、2、8、9 条）与**入口补齐**（第 10 条）。
