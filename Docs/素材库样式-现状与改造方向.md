## 二、问题根源：两套互不相干的卡片体系

| | 体系 A（Button 壳） | 体系 B（GridViewItem 壳） |
|---|---|---|
| 基类 | `Button` | `GridViewItem` |
| 代码 | `Views/CardShell.cs`（137 行，带完整规章注释） | `Views/GridViewItemFactory.cs` + `DashboardCardFactory.cs` + `CardContentFactory.cs` |
| 尺寸 | 280×76 / 272×153 / 190×220 | 260×318 / 236×294 |
| 间距 | 12（CardShell.CardGap） | 18（CreateDashboardCard）/ 14（默认） |
| 用在 | 素材库**详情**页 | 素材库**列表**页、项目详情页 |

同一个功能的两级页面，进去之后尺寸、圆角、间距全变 —— 这是"不统一"的直接观感来源。

`CardShell.cs:8-22` 已经把规章写清楚了：**卡片就是 Button 自己、不套 Border、不设底色（悬停交给系统状态色）、1px CardStrokeColorDefaultBrush + 圆角 8**。但规章只覆盖 A 体系。

## 三、具体不一致点

| 项 | 现状 | 出处 |
|---|---|---|
| 圆角 | **6** 与 **8** 混用 | `PanelBorderStyle`=6；`CardButtonStyle`=8；`CardContentFactory`=6 |
| 间距 | **12 / 14 / 18** 三种 | CardShell.CardGap=12；GridViewItemFactory 默认 14；CreateDashboardCard=18 |
| 字号 | 16/12（A）、24/12/78（B） | `CardShell` vs `CardContentFactory` |
| 图标按钮 | 每次现写 `40×40 / CornerRadius=6` | `AssetBrowser.xaml` 三个按钮 |
| 主题画笔 | 3 处用 `Application.Current.Resources[...]` | `CharacterDetail.cs:529/536`、`Utilities.cs:49` |

**最后一条是已知坑**：夜间模式切的是元素 `RequestedTheme`，而 `Application.Current.Resources` 拿到的是应用级主题 → 拿错画笔。`CardShell.cs:87-90` 有明确记录（2026-10-17 出过"黑底黑字"）。

## 四、样式定义散落在四层

1. `App.xaml`：`PanelBorderStyle` / `PageTitleStyle` / `SectionTitleStyle` / `SubtleTextStyle` /
   `CardButtonStyle` / `AssetGridViewStyle` / `PaddedAssetGridViewStyle` / `HelpIconButtonStyle`
2. `Views/CardShell.cs` 常量：尺寸 + 字号 + 圆角 + 内边距
3. `Views/CardContentFactory.cs` 硬编码：Height 294、FontSize 24/12/78、Width 236、CornerRadius 6
4. 页面 XAML 里零散写 `Width=40 Height=40 CornerRadius=6`

改一处样式要翻四个地方 —— 这是重做时首先要收拢的。

---

## 五、改造的两个层次

### L1：统一词汇（改动小，1~2 小时）

- 建 `DesignTokens`：圆角 8、间距 12、字号 16/12、卡片尺寸阶梯 76 / 153 / 220 / 318；
- 把散落的 6 / 14 / 18 全部换掉；
- 图标按钮抽成 `IconButtonStyle`；
- 3 处主题画笔改成 `ThemeResource` 或继承前景色 + 降透明度。

视觉立刻整齐，但两套体系还在。

### L2：合并卡片体系（改动大，半天以上）

把 B 体系（260×318 的 GridViewItem）迁到 CardShell 的 Button 形态。代价：

- 素材库列表页 + 项目详情页的卡片要重写；
- GridView 的 `CanDragItems` / `DragItemsCompleted`（素材重排靠它）要挪到 Button 的 `CanDrag` + Drop 上；
- GridView 自带选中态视觉要自己补。

换来"全项目一种卡片，一处改全改"。

**建议：先做 L1**，再看是否值得 L2。L1 之后尺寸差距从"260 vs 280"变成"同一阶梯的两档"，观感上已经能接受；L2 会碰拖拽重排，属于"能用但容易碰坏"的区域。
