| 按钮 | 行为 | 改文件吗 |

| 检查DB规范 | 量当前章节 `Voice/{章节代号}/*.wav` 的积分响度与真峰值，按游戏语音口径判成「达标 / 贴边 / 超差 / 峰值超」，并额外出**同类离散度** | 否，只读 |

口径（唯一定义处 `Models/VoiceLoudnessModels.cs` 的 `VoiceLoudnessPreset.GameDialogue`）：

| 项 | 值 | 依据 |
|---|---|---|
| 目标积分响度 | −12 LUFS | 隔壁预设表里游戏档的**对白锚点**（两套中文参考资料一致） |
| 容差 | ±2 LU | 同上；容差一半以内算「达标」，容差内算「贴边」 |
| 真峰值上限 | −3 dBTP | 同上，游戏档全类别共用 |
| 判定文案 | 「按业界惯例建议范围」 | 游戏档**没有官方标准**，不许说「合规」 |

没搬的：电影/EBU 那套预设（−23 LUFS / −1 dBTP）、裁首尾静音、音效链、输出格式与声道选项。
理由：这条链路只有「一句话一条」的语音，那些开关不产生价值，只会多一层误操作。

## 3. 三条硬决策（都有实测依据）

### 3.1 落盘必须显式给 `-ar`，否则成品变 192 kHz

`loudnorm` 为了测真峰值内部升采样到 192 kHz，**不给输出采样率就按 192 kHz 写 wav**。
2026-11-02 实测（同一条 2.4 s / 44.1 kHz 素材）：

| 命令 | 成品 | 体积 |
|---|---|---|
| 带 `-ar 44100` | 44100 Hz, mono | 207 KiB |
| 不带 `-ar` | **192000 Hz**, mono | 900 KiB |

所以 `VoiceBatchProcessor` 从 `-i` 的头信息里读源采样率（`ParseSampleRate`）再原样喂回；
读不到才退到 48000 并写一行警告。**这一条不修，语音在 Unreal 里的体积和导入耗时都会翻几倍。**

### 3.2 两遍法，量不出来就不动文件

测量与落盘施加的是**同一串滤镜参数**，两段之间没有任何会改波形的中间步骤
（隔壁实测：滤镜施加两次会让增益偏 0.6~2.4 dB，且不报错）。
规整前先测量；**量不出来直接跳过这一条**，不做「单遍动态」兜底 ——
就地覆盖不可逆，没测量值的结果事后无法回溯。

### 3.3 先整章备份，再逐条「临时件 → 替换」

备份落 `{项目}/Tools/AudioBackups/{yyyyMMdd-HHmmss}_{章节}/`，
临时件与源文件同目录（同卷替换），失败只删临时件。备份失败直接抛：没有回退点的批量替换不该开始。

## 4. 实测证据（2026-11-02，真实素材）

素材：`G:\NewData\GalExcelProject\项目-我喜欢的白发美少女不可能是凶手_1\Voice\WHK-M1-00\Vo-094-笨蛋S1.wav`

| 阶段 | 积分响度 | 真峰值 | 采样率 |
|---|---|---|---|
| 源 | −9.44 LUFS | −1.00 dBTP | 48000 Hz |
| 规整后 | **−12.01 LUFS** | −3.55 dBTP | **48000 Hz** |

→ 两遍法在真实语音上确实落在 −12 附近，采样率保持不变。

**同章其它文件的现状**（只量不改，抽样）：−9.44 / −10.14 / −10.75 / −12.50 LUFS，
真峰值全部**恰好 −1.00 dBTP** —— 说明这批语音此前已经被限制到 −1 dBTP。
峰均比约 9 dB，恰好压在「−12 目标 + −3 天花板」能否同时满足的边界上，
所以规整时**有一部分会顶在天花板上、落不到 −12**，报告里会单独解释这一段
（`VoiceComplianceItem.IsPeakLimited`，判据两条：目标对该峰均比不可达 + 成品确实贴着天花板）。

## 5. 包体影响（必须先知道）

随包 ffmpeg 是 150 MB（`Tools/Audio/ffmpeg`，7 个文件，最大 `avcodec-63.dll` 91 MB）。
`csproj` 早就把 `Tools\**\*` 当 Content 复制，所以**不用改工程文件**，但：

- 输出目录和发布包会直接多出 150 MB；
- 本项目此前 ~99 MB，已贴着 Gitee 单附件 100 MiB 的墙 —— 加完之后**必然要走分卷**
  （`Docs/热更新-分卷与双通道-契约.md` 里那套 `…partNN.zip`）。
