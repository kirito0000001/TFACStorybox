## 1. 做了什么

| 按钮 | 行为 | 改文件吗 |
|---|---|---|
| 检查DB规范 | 量当前章节 `Voice/{章节代号}/*.wav` 的积分响度与真峰值，按游戏语音口径判成「达标 / 贴边 / 超差 / 峰值超」，**结论直接写进表格的 DB 列并落缓存**（不再弹报告窗） | 否，只读 |
| 规整语音 | 两遍 `loudnorm` 把每条拉到目标响度、峰值压到天花板下，**就地覆盖**（回退靠「原始版」，见 §8）。平时灰着，只有 DB 列里存在「可修的」超差项时才可点，**点了直接执行、不再弹确认框** | 是 |

表格新增 **DB 列**（列序：文本 / 语音文件 / DB / 试听）：常驻显示每条语音的 `LUFS · dBTP · LRA`，
其中 LUFS 按判定染色 —— 容差内绿、超出容差且偏响红、超出容差且偏轻黄；没语音或没查过显示灰色横线。
数据来自**上一次手动检查**（缓存 `{项目}/Tools/VoiceLoudness/{章节}.json`），**进页面不自动测量**。

口径（唯一定义处 `Models/VoiceLoudnessModels.cs` 的 `VoiceLoudnessPreset.GameDialogue`）：

| 项 | 值 | 依据 |
|---|---|---|
| 目标积分响度 | −12 LUFS | 隔壁预设表里游戏档的**对白锚点**（两套中文参考资料一致） |
| 容差 | ±2 LU | 同上；容差一半以内算「达标」，容差内算「贴边」 |
| 真峰值上限 | −3 dBTP | 同上，游戏档全类别共用 |
| 判定文案 | 「按业界惯例建议范围」 | 游戏档**没有官方标准**，不许说「合规」 |

没搬的：电影/EBU 那套预设（−23 LUFS / −1 dBTP）、裁首尾静音、音效链、输出格式与声道选项。
理由：这条链路只有「一句话一条」的语音，那些开关不产生价值，只会多一层误操作。

## 3. 三条硬决策（都有实测依据）

### 3.1 落盘必须显式给 `-ar`，否则成品变 192 kHz

`loudnorm` 为了测真峰值内部升采样到 192 kHz，**不给输出采样率就按 192 kHz 写 wav**。
2026-11-02 实测（同一条 2.4 s / 44.1 kHz 素材）：

| 命令 | 成品 | 体积 |
|---|---|---|
| 带 `-ar 44100` | 44100 Hz, mono | 207 KiB |
| 不带 `-ar` | **192000 Hz**, mono | 900 KiB |

所以 `VoiceBatchProcessor` 从 `-i` 的头信息里读源采样率（`ParseSampleRate`）再原样喂回；
读不到才退到 48000 并写一行警告。**这一条不修，语音在 Unreal 里的体积和导入耗时都会翻几倍。**

### 3.2 两遍法，量不出来就不动文件

测量与落盘施加的是**同一串滤镜参数**，两段之间没有任何会改波形的中间步骤
（隔壁实测：滤镜施加两次会让增益偏 0.6~2.4 dB，且不报错）。
规整前先测量；**量不出来直接跳过这一条**，不做「单遍动态」兜底 ——
就地覆盖不可逆，没测量值的结果事后无法回溯。

### 3.3 回退靠「原始版」，不再整章复制

**已改（2026-11-02 晚，见 §8）**：原方案是每次规整把整章复制到
`Tools/AudioBackups/{时间戳}_{章节}`，规整十次就是十份整章。现在改成
`Tools/VoiceOriginals/{章节}/` 下每个工作文件固定一份**最初副本**，规整只覆盖工作版。
逐条「临时件 → 替换」的写法不变（失败只删临时件，原文件一个字节不动）。

## 4. 实测证据（2026-11-02，真实素材）

素材：`G:\NewData\GalExcelProject\项目-我喜欢的白发美少女不可能是凶手_1\Voice\WHK-M1-00\Vo-094-笨蛋S1.wav`

| 阶段 | 积分响度 | 真峰值 | 采样率 |
|---|---|---|---|
| 源 | −9.44 LUFS | −1.00 dBTP | 48000 Hz |
| 规整后 | **−12.01 LUFS** | −3.55 dBTP | **48000 Hz** |

→ 两遍法在真实语音上确实落在 −12 附近，采样率保持不变。

**同章其它文件的现状**（只量不改，抽样）：−9.44 / −10.14 / −10.75 / −12.50 LUFS，
真峰值全部**恰好 −1.00 dBTP** —— 说明这批语音此前已经被限制到 −1 dBTP。
峰均比约 9 dB，恰好压在「−12 目标 + −3 天花板」能否同时满足的边界上，
所以规整时**有一部分会顶在天花板上、落不到 −12**，报告里会单独解释这一段
（`VoiceComplianceItem.IsPeakLimited`，判据两条：目标对该峰均比不可达 + 成品确实贴着天花板）。

## 7. 同日改版：DB 列 / 纯手动 / 去弹窗（2026-11-02 晚）

用户看完第一版截图后定的三条：

1. **列宽**：文本砍 1/3、语音砍一半，空出来的位置放新列。实现是 `文本 4* : 语音 3* : DB 固定 320 : 试听 72`，
   语音按钮的 `MinWidth` 从 520 降到 240 —— **520 会把列顶回去，DB 列就没地方站了**。
   星号列永远吃满剩余空间，所以 DB 必须是固定宽，否则文本根本窄不下来。
2. **DB 列常驻元数据**：显示 `LUFS · dBTP · LRA`，LUFS 按 `ClassifyLoudness` 染色
   （绿=容差内 / 红=超出且偏响 / 黄=超出且偏轻）；没语音、没查过都是灰色横线。
   没语音的行只造一个 TextBlock，不登记进字典（366 行里只有 26 行有语音，省下 680 个控件）。
3. **不自动测量**：进页面只读缓存（`Tools/VoiceLoudness/{章节}.json`，按「文件名 + 字节数 +
   最后写入时间」判新鲜度），量不量由用户点「检查DB规范」决定。第一版曾做「后台逐条补测」，
   被明确否掉。
4. **去掉检查报告弹窗**：结论直接写回 DB 列；浮条只报一行总量，完整统计（含同类离散度）进 Log。
   `BuildVoiceComplianceReportView` 及配套的四个绘制方法随之删除（不留死代码）。
5. **按钮改名「规整语音」并默认禁用**：`IsEnabled` 只由「DB 列里存在**可修的**超差项」决定
   （`item.Measurement.IsUsable && item.NeedsFix`）。刻意排除「测不出」的条目 ——
   它们也判 NeedsFix，但规整同样修不了，让按钮为它们常亮等于给一个点了没用的入口。
6. 规整完成后**不重铺页面**（会丢滚动位置），只就地更新 DB 单元格与缓存。

## 8. 备份改版：只留一份「原始版」（2026-11-02 晚）

用户提法：「导入的时候直接存两份，一个作为最原始的数据，另一份随便改、用于同步」。
落地就是这个设计，落点 `Tools/VoiceOriginals/{章节}/{工作文件名}.wav`。

### 8.1 语义（先定清楚，否则「最初的到底是哪一版」会一直吵）

| 动作 | 工作版 | 原始版 |
|---|---|---|
| 通过界面导入 / 更换语音 | 写入并改名成 `Vo-xxx-备注.wav` | **覆盖**成这份新素材 |
| 改备注（只重命名） | 改名 | **跟着改名**，内容不动 |
| 规整语音 | 就地覆盖 | **不动** |
| 移除语音 | 删除 | 一并删除（同一个工作文件被别的行引用时保留） |
| 存量文件（机制之前就导入的）第一次规整 | — | **补存当前状态**，此后一直复用 |

也就是：**原始版 = 最近一次通过界面导入的原文件**，规整永远污染不到它。

### 8.2 三个容易写错的地方

1. **命名跟工作版走**，不能跟用户选的原文件走。用户选 `record_001.wav`，工作版会被改名成
   `Vo-094-笨蛋.wav`；若按源文件名存原始版，还原时按工作名找永远找不到 —— 而且是静默失效。
   内容仍从源文件复制（工作版可能刚被重命名，也可能已被别的东西改过）。
2. **改备注会重命名工作文件**，原始版必须跟着 `File.Move`，否则同上。
3. **不能放在 `Voice/` 里**：Voice 的枚举是 AllDirectories，放进去会被当成一条语音一起检查、
   一起规整、一起同步进 Unreal。所以落 `Tools/`（工具箱私有区）。

### 8.3 配套改动

- 「规整语音」**去掉确认框**，点了直接跑：有了原始版兜底，「就地覆盖」不再是不可逆操作。
- 完成时**全成功只弹浮条**（并报「N 条受峰值天花板限制未到目标」），有失败才弹窗逐条读原因。
- 语音按钮右键新增「**还原最初版**」。还原后该行响度结论立即作废、DB 退回横线，
  必须重新点检查 —— 不能让它继续显示还原前的数字。
- 旧的 `Tools/AudioBackups/{时间戳}_{章节}` 机制整套删除（`CreateBackup`、
  `VoiceNormalizeResult.BackupDirectory`、`GetProjectAudioBackupsFolderPath` 一并去掉）。
  历史目录里如果还有文件，可以直接删。
