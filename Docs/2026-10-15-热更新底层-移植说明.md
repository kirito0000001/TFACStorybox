## 与本项目实现的差异

1. **只走 Gitee 一个源。** 参考项目在设计上就砍掉了 GitHub 回退；本项目原来的双源回退（Gitee 失败再试 GitHub）不再存在。
2. **版本号读取多了一级。** `ApplicationVersionReader` 先读 exe 同级的 `ax-app-version.json`，再回退程序集元数据。AX 工具箱靠这个旁挂文件把同一份源码编成不同版本号的产物。
3. **出包改用本项目原有的 `Scripts\Package-App.ps1`。** `Build-GalExcelUpdatePackage.ps1` 以 `-SkipUpdateAssets` 调它，只让它产出程序目录；zip / sha256 / `toolbox-update.json` / 台账仍由出包脚本自己出，避免两个真源。
4. **`Assert-ZdPackageStructure` 的必需清单换成本项目真实载荷**：`ax-app-version.json`、`Tools\UnrealBridge\run_remote_unreal_job.py`、`Tools\UnrealBridge\execute_remote_unreal_job.py`、`Scripts\update-whitelist.json`、`Scripts\热更新覆盖.ps1`（参考项目要的 `Tools\Atlas\**` 本项目没有）。
5. **凭据环境变量改名**为 `GALEXCEL_GITEE_TOKEN` / `GALEXCEL_GITHUB_TOKEN`（`GITEE_TOKEN` / `GITEE_ACCESS_TOKEN` / `GITHUB_TOKEN` / `GH_TOKEN` 等标准回退保留）。
6. **修了三个移植过来的缺陷**：① `[CmdletBinding()]` 脚本的 param 默认值里读 `$PSScriptRoot` 拿到空串（改为在函数体里兜底解析）；② `GalExcelPublish.ps1` 在 `Set-StrictMode` 下直接读可选的 `$manifest.delta` 会抛「找不到属性 delta」（改走 `Get-ZdOptionalProperty`）；③ `Scripts\Package-App.ps1`、`Scripts\Publish-GiteeRelease.ps1` 补了 UTF-8 BOM（原来在 Windows PowerShell 5.1 下中文把引号吃掉、直接语法错误）。
7. **Debug 构建不做启动自动检查**（设置页那句说明就是这么写的）；手动「检查更新 / 下载并更新」不受影响。

## 验证

客户端侧用替身 HTTP 跑过完整链路（检查 → 组 plan → 下载 → 大小 / magic / SHA-256 / 包结构四道校验 → 缓存复用）与一组 fail-closed 用例（限流 / 404 / 缺清单 / 标识不符 / 线上更低 / 需手动迁移 / 无本机 runtime 的包 / 哈希不符 / 包内缺 `update-package.json` / 包内版本不符），加上与覆盖器的跨语言参数与信号契约、白名单两侧同判定，以及一次真实匿名 Gitee 往返；发布侧用 `Publish-GalExcelRelease.ps1 -DryRun` 跑通出包 → 清单 → 台账 → 复用并 exit 0，产出的 `toolbox-update.json` 与客户端读取的字段一致。

## 已知遗留

1. `Scripts\` 下还有 32 个 `Test-*.ps1` 没有 UTF-8 BOM 却含中文，在 Windows PowerShell 5.1 下会解析失败（本次只补了发布链路用到的两个脚本）。
2. 出包脚本的 `-IncrementalBuild` 在本项目的打包器上没有对应能力，会退化成全量重建并打印一行提示。
