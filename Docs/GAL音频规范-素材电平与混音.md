## 一、结论速查

| 素材 | 素材电平 | 真峰 | 引擎滑块 | 运行时听感 |
|---|---|---|---|---|
| 语音（单句） | **−18 LUFS** | ≤ −1 dBTP（实测中位 −1.1） | 100% | −18 |
| BGM（有滑块） | **−12 LUFS** | 可削波（实测 +0.45） | **50%** + ducking | ≈ −18 |
| BGM（无滑块） | **−24 LUFS** | ≤ −1 dBTP | — | −24 |
| SE（剧情内） | 按峰值：**−4.5 dBTP** | −4.5 | 80% | — |
| SE（系统/按键） | 峰值再低 3~4 dB | ≈ −8 | 50% | — |

> 一句话：**语音留 6 dB 余量给 BGM，靠滑块和 ducking 拉平；没有滑块就把这 6 dB 做进素材。**

## 二、实测数据

### 语音（voice.xp3，183 条随机样本）

| 分位 | LUFS |
|---|---|
| 10% | −24.60 |
| 25% | −21.60 |
| **50%** | **−18.00** |
| 75% | −14.80 |
| 90% | −11.80 |

- 均值 −18.59，标准差 **6.50**
- 真峰：中位 −1.10 dBTP，最大 +1.50，**48% 在 −1 以上**
- LRA：中位 **1.6**，25~75% 为 0.0 ~ 3.2

**解读**

1. 中位正好是 −18，和 IESD/Wwise 的"对白参考值"对齐；
2. 标准差 6.5 说明**按内容做**（耳语轻、喊叫重），不是把每条都压到同一刻度；
3. 近一半素材真峰超过 −1 dBTP —— **−1 是安全上限，不是硬规范**；
4. 单句 LRA 1.6 是常态，不是缺陷（整段场景才需要 5~8 LU）。

### BGM（bgm.xp3，105 条）

| 指标 | 数值 |
|---|---|
| LUFS 中位 | **−11.95** |
| 真峰中位 | **+0.45 dBTP**（母带削波） |
| 真峰最大 | +2.60 |

比语音**响 6.2 dB**，且母带不避讳削波。

### 音效（data.xp3，240 条）

| 指标 | 数值 |
|---|---|
| 峰值中位 | **−4.50 dBTP** |
| 峰值范围 | −20.10 ~ +1.90 |

> 短音效（0.1~1 秒）的 LUFS 因门控不可靠，**音效一律看峰值**。

### 游戏内默认音量（设置界面）

```
主音量            100
语音（剧情内）     100
BGM                50      ← 关键
BGM（语音播放时）   50      「不降低 BGM 音量」未勾选 = 开启 ducking
SE（剧情内）        80
SE（系统音效）      50
系统语音           100
影像 70 / 演奏 100 / BGV 70
角色语音设定        100
```

**换算验证**

```
BGM  −11.95 LUFS × 50%（−6.02 dB）= −17.97
语音 −18.20 LUFS × 100%           = −18.20
差 0.23 dB → 听感上完全贴合
```

## 三、落地到本项目

### 当前链路（`VoiceLoudnessPreset.GameDialogue`）

```
目标 −18 LUFS ±2 LU
真峰天花板 −1 dBTP（限幅器 limit=0.85 ≈ −1.4 dBFS）
链路：volume=<目标−实测>dB, alimiter=limit=0.85:attack=12:release=50
去噪：UVR，可选，放在响度之后
```

### 与参考作品对照

| 项 | 参考 | 本项目 | 判断 |
|---|---|---|---|
| 语音目标 | −18.0 | −18 | ✅ 一致 |
| 语音真峰 | 中位 −1.1，48% 超 −1 | ≤ −1.4 | ✅ 更保守，可放宽 |
| LRA | 中位 1.6 | 1.5 ~ 2.8 | ✅ 一致 |
| BGM | −12 + 50% 滑块 | 未定 | ⚠️ 待定 |
| SE | 峰值 −4.5 | 未定 | ⚠️ 待定 |

### 建议

1. **语音目标保持 −18，不用改。**
2. **真峰天花板可放宽到 −1.0**（limit 0.85 → 0.89）：参考作品近一半素材都在 −1 以上，我们没必要比商业成品更保守。
3. **BGM 分两种情况**：
   - 引擎有独立 BGM 滑块 → 素材做 −12，默认 50%；
   - 引擎没有 → 素材直接做 **−24**，否则一定盖住语音。
4. **SE 用峰值定标**，不要用 LUFS：剧情内 −4.5 dBTP，系统/按键再低 3~4 dB。

## 四、为什么"统一拉到 −18"在原件上做不到

需要压缩的量由**峰均比**决定：

```
需要的压缩量 = 峰均比（真峰 − 响度）− 9 dB
```

| 素材 | 响度 | 真峰 | 峰均比 | 需压缩 |
|---|---|---|---|---|
| 参考作品（正常录音） | −18 | −5 | 13 | 4 dB ✅ 听不出 |
| 本项目素材 | −34 | −15 | 19 | 10 dB ❌ 必然发闷 |

所以"这批素材到不了 −12"从来不是链路问题，而是**素材电平太低、峰均比太高**。改目标到 −18 后，需要的压缩量降到 0~2 dB，问题自然消失。
