# 小节「自定义跳转逻辑」：封存说明

> 状态：**已封存**（2026-10-15）。小节那边的 UI 入口删掉了，数据与逻辑一行没动。
> 结论：这个功能的位置该在**选项**那边（选项管理器里本来就有同一个标记的入口），
> 不在「行与小节」里；而且它承诺的效果（"同步时保留手工设置"）在当前的同步实现下
> **并不成立** —— 所以在修好之前，不该继续在界面上摆着。
> 版本：TFAC剧情箱-轮椅版 2.3.0
> 相关：`Docs/2026-10-12-虚幻同步台-对比与改造方向.md`（AllRoad 那一节）

---

## 0. 一句话

它管的是**这一节的 AllRoad 跳转归谁**：

- **关**（原 OffContent「自动同步」）＝ 工具箱说了算：每次同步按小节结构自动生成这一节的跳转。
- **开**（原 OnContent「保留手工设置」）＝ 你在 Unreal 里手工配的那套别动。

跟素材、剧情表、CSV、语音都**无关** —— 名字里的"同步"特指 `ExcelTexts/AllRoad` 那张跳转表。
这也正是它不该长在按句编辑的工具区里的原因。

---

## 1. 它原本怎么工作（机制）

1. 打开开关 → 把**这一节第一行的 StableId** 记进 `story.document.json` 的
   `CustomBranchSectionFirstRowIds`
   （`Services/StoryBranchService.cs:237-257`、`Models/StoryDocument.cs:17`）。
   → 按**小节**记的，并且跟"小节第一行"这个身份绑定（所以删掉小节第一句、
   或拆分/合并小节时，标记要不要跟着挪是有讲究的，见第 3 节）。
2. 同步时小节流图把这一节标成 `StoryBranchSectionKind.Custom`，AllRoad 生成跳过它
   （`Services/UnrealSyncService.cs:2041-2048`）—— 也就是**不给 Unreal 写这一节的条目**。
3. 同一个标记在**选项管理器**里还有一个入口，那里的措辞更准确：
   「同步方式 / 工具箱管理 ↔ Unreal 手工管理」
   （`MainWindow.xaml:2265`、`MainWindow.Workbench.ChoiceManager.cs:245-254`、
   `Services/StoryChoiceManagerService.cs:52-56`）。

**什么时候用它**：你在 Unreal 里手工给这一节配了跳转（工具箱推不出来的那种：
特殊条件、跳到别的章节/别的表），又不想每次同步被自动生成覆盖。

---

## 2. 为什么要封存

### 2.1 位置不对

它同步的是"选项跳转关系"，却长在按句编辑的工具区里。同一个标记在选项管理器里已经有入口，
而且那边的措辞（工具箱管理 / Unreal 手工管理）比小节这边的（自动同步 / 保留手工设置）准确 ——
后者容易被读成"这一节的**内容**要不要同步"。一句话：**该在选项那边。**

### 2.2 承诺没兑现（更要紧）

AllRoad 的**写入**在 2026-10-12 改成了「**整表重建**」（`Services/UnrealSyncService.cs:1020-1051`）：
Python 会把落在 `ExcelTexts/MainStory` 下的旧条目**全部清掉**，再按本次计划写回。

而被标成 Custom 的小节**不在计划里** → 不会被写回 → 结果是它的条目**被删掉**，
而不是"保留"。开关开着，手工配的跳转下一次同步就没了，而且全程不报错。

**触发条件**（两条同时成立才会发生）：

- 同一章里还有**非自定义**的小节 —— 那个 manager 行有 sources，重建就会跑；
- 这一章的表落在 `ExcelTexts/MainStory` 下，也就是 **MainThread 章节**。

**反面**：Interlude 之类的章节，因为那段清理范围把 `MainStory` 写死了，
旧条目反而**永远清不掉**（同一个根因的另一面）。

**历史对照**：旧写法是"只删与本次来源同路径的条目"（见 `Services/UnrealSyncService.cs:1027-1037`
那段注释），那种写法**不会**碰自定义小节 —— 是这次"重建"把它带走的。

## 3. 封存后的现状（2026-10-15）

### 删掉的（小节侧）

- `MainWindow.xaml` 里那个 ToggleSwitch（原 `x:Name="StoryCustomBranchLogicToggle"`，
  位置在「行与小节」工具区，已换成一段说明注释）。
- `MainWindow.Story.Sections.cs` 里的 `UpdateStoryCustomBranchLogicToggle`、
  `StoryCustomBranchLogicToggle_Toggled`、字段 `_isUpdatingStoryCustomBranchLogicToggle`。
- 它的三处调用：换行载入（`MainWindow.Story.cs` 的 `LoadStoryRowIntoUi`）、
  拆分小节后重算、合并小节后重算。

> 删掉的原因还有一条：它当时是"把当前小节标成自定义"的**唯一带撤销的入口**
> （一次 Ctrl+Z 能退回）。入口收走之后，这条也就不存在了 —— 解封时要一并想清楚。

### 保留的（数据与逻辑，一行没动）

- `StoryDocument.CustomBranchSectionFirstRowIds` 本体、存盘、撤销/重做变更集。
- `StoryBranchService.IsCustomBranchSection` / `SetCustomBranchSection`，
  以及**删除句子时把锚点顺延**（含这个标记，`Services/StoryBranchService.cs:153-235`）。
- `StoryBranchFlowService` 的 `StoryBranchSectionKind.Custom`，以及同步侧跳过它的那一步。
- 拆分 / 合并小节时对标记的处理：**合并时两节里只要有一节标着，合并后继续标着**
  （否则合并会把手工 AllRoad 变成"下次同步自动重建"）。

理由：旧文档里可能就带着标记，选项管理器也还能改它 —— 这些行为不能跟着 UI 一起消失。

### ⚠️ 还开着的入口

选项管理器里那个「同步方式」开关是**同一个标记、同一段未修的同步行为**，
也就是说 2.2 那条**仍然可以从那里触发**。要不要连它一起收起来，等确认后再动
（收起来 = 那个开关藏掉或改成只读，`CustomBranchSectionFirstRowIds` 仍然保留）。

---

## 4. 解封要做的事

1. **换位置**：入口放选项那边（选项管理器已经是了），小节工具区不再放。
2. **把"自定义"告诉 Unreal**：manifest 的 `StoryBranches` 里加一份 `PreserveSources`
   （这些小节各自的表路径），Python 重建 `rebuilt_story_map` 时把这些 key 原样留下。
   —— 不告诉它，重建就一定会把条目清掉，这条是解封的**前提**。
3. **顺手修清理范围**：`managed_story_root` 现在硬编码 `.../ExcelTexts/MainStory`，
   改成"该 manager 行本次涉及的表所在目录"（这样 Interlude 那些也才清得干净）。
4. **补检查**：`Scripts/Test-UnrealStoryBranches.ps1` 现在钉的是
   "小节侧开关不许长回来 + 选项管理器入口仍在"；解封时补一条
   "被标 Custom 的表条目在重建之后仍然在"。

---

## 5. 复现（验证 2.2 那个 bug）

1. 建两节（「创建新小节」），在某节上打开标记（现在只能从选项管理器开）。
2. 在 Unreal 里给这一节手工配一条跳转，或者先记下 AllRoad 里这一节的条目。
3. 改点别的，让它触发一次含 StoryBranches 的同步（改选项、改小节边界都行）。
4. 同步后看 AllRoad：这一节的条目**没了** —— 既不是被保留，也不是被换成自动生成的那条。
