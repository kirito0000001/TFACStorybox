# 报错时自动打开日志面板（2026-11-03）

> 需求原话：「报错时自动启动日志系统，这样子我可以直接复制日志。平时工作不会开启日志系统，
> 那样会占工作空间，但是报错出现时去开就迟了，之后不好复现。」

## 1. 先厘清现状（和直觉不一样）

| 层 | 由谁控制 | 实际情况 |
|---|---|---|
| `%LOCALAPPDATA%\GalExcleTools\Logs\runtime.log` | **不受任何开关控制** | `AppendLog` 里先写文件、再判开关 —— **一直都是全量** |
| 界面日志面板 | `Settings.LogEnabled` | 关着时整个面板 `Collapsed` |
| 面板里的条目 | `ShouldWriteLog(kind)` | `LogEnabled=false` 时**连内存队列都不入**（Info/User 全丢） |

所以「报错后去开就迟了」真正的损失不是文件，而是**面板里的上下文**：
错误发生时面板要么不存在，要么只有孤零零一条 Error —— 看不出它前面发生了什么。

> 注：`Error` / `Warning` 两档在 `ShouldWriteLog` 里**永远返回 true**（2026-10-12 加的特例），
> 但那个判断排在最前面的 `if (!LogEnabled) return false;` 之后，所以开关关着时它们同样进不来。

## 2. 改动

### 2.1 队列改为无条件收集

`AppendLog` 里原来是这样：

```csharp
if (!ShouldWriteLog(kind)) return;   // ← 连队都不入
_logLines.Enqueue(...);
```

现在**先入队**（环形上限 300 条），再把过滤挪到**渲染层**：

- 收归收，显示归显示。开关只决定"看不看得到"，不该决定"留不留证据"；
- 这样报错那一刻，队列里已经有最多 300 条历史（含被过滤掉的 Info/User）。

### 2.2 Error 触发面板自动打开（仅本次运行）

```csharp
if (kind == LogKind.Error && !Settings.LogEnabled && !_autoLogPanelVisible)
{
    EnableLogPanelForSession();   // 显示面板 + 重新渲染 + 浮条提示
    return;
}
```

- `_autoLogPanelVisible` 是**纯内存标记**，不写 `settings.json`：
  用户关日志就是为了省地方，自动打开如果落了盘，下次启动还开着，等于替他改了设置。
- 面板一打开就重渲染，队列里的上下文一次性铺满 —— `复制全部` 拿到的就是完整现场。
- 用户在设置里自己动开关时清掉这个标记，以他的选择为准。

### 2.3 未处理异常也写进同一个文件

`App_UnhandledException` 原来只写 `%APPDATA%\GalExcleTools\crash.log`。现在**同时**往
`runtime.log` 追加一条 `[Fatal]`：这条路是进程马上要没，面板救不回来，能留的只有文件，
而用户平时只认 `runtime.log` 一个路径。

## 3. 行为对照

| 场景 | 改动前 | 改动后 |
|---|---|---|
| 平时（日志关） | 面板隐藏，内存不攒 | 面板隐藏，但内存攒最近 300 条 |
| 发生一条 Error | 面板仍隐藏（要去设置里勾） | 面板自动弹出，含报错前上下文，可一键复制 |
| 用户手动改开关 | — | 以用户选择为准，自动标记清掉 |
| 进程崩溃 | 只有 crash.log | crash.log + runtime.log 各一份 |
| 设置是否被改 | — | **不改**，重启恢复原样 |
